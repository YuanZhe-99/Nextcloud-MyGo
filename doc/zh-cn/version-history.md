# 版本历史

## 0.1.1

Windows 按需文件，依据用户 2026-11-14 的决定。

- **按需文件。** 目录把每个远程文件保留为占位文件，应用打开时才下载（Windows Cloud Files）。新目录默认按需；
  仍可选择完整文件。Cloud Files 可运行时该能力开启。
- **0.1.0 添加的目录自动切换一次。** SyncD 在启动时把它们的文件变成已同步的占位文件，不下载、不删除、不上传任何内容，
  也不写 journal：自上次同步以来已变化的文件和无法打开的文件保持普通状态，直到第一个周期把它们变成占位文件；
  无法切换的目录（位于另一个应用同步的目录内、位于网络驱动器上）保持完整文件，并在每次启动时重试。目录所在行会说明发生了什么或为何没有发生。
- **资源管理器。** 每个按需目录都有名为“Nextcloud MyGo - <目录名>”的导航窗格条目，同步根显示 Nextcloud 图标。
- **卸载先释放按需目录。** 已下载的文件变为普通文件，仅联机占位文件在本地被删除（服务器仍保存它们），
  任何目录无法释放时都不删除任何内容。完整文件目录、journal、账号和设置保留。
- **验收发现的两处修复。** 按需目录中的本地删除从未到达服务器（目录停在 `SYNC_FAILED`）：补丁 0020 让 SyncD 在周期之间携带上游的重启标志，重启的周期不算失败。普通稀疏文件曾被读作仅在线的占位文件，在本地被删除或没有上传：补丁 0021 要求占位文件的召回标志，稀疏文件与其他文件一样被转换（[按需文件](on-demand.md#本地删除与稀疏文件)）。
- **第一个周期的竞态。** 按需目录的第一个周期运行时，另一个进程可能向 Cloud Files 请求目录列表；列表先创建了占位文件，周期过去会以 `SYNC_FAILED` 结束。SyncD 现在识别这种情况（占位文件持有相同的服务器文件 ID）并报告为重启周期，连续只豁免一次（[按需文件](on-demand.md#本地删除)）。
- **同一秒内的 ETag 已处理。** Nextcloud 35.0.3 在文件于一秒内被重写两次时可能保留其 ETag，因此在本地也被编辑的文件可能替换服务器上较新的内容。补丁 0022 把 ETag 相等时服务器大小不同视为服务器端变化：文件被下载，若本地也被编辑则成为冲突副本。仍无法检测：一秒内的同大小重写，以及父目录也保留其 ETag 的服务器上的重写（[按需文件](on-demand.md#已知风险)）。
- **列表标识。** 补丁 0023 精确存储由 Cloud Files 列表创建的占位文件的文件标识，不再带有越过缓冲区读出的字节（[上游](upstream.md#nextcloud-desktop)）。
- 协议 1.11 与 Control schema 12（每个目录的转换状态）。新增上游补丁 0020 至 0023（共 23 个，指纹 `CF0C68C10DD7`）。

已知限制：

- 降级：0.1.0 拒绝 schema 12 的数据库。请先在 0.1.1 中移除这些目录，再重新安装 0.1.0。
- 卸载只处理正在运行的 profile；没有目录支撑的 Windows 注册（例如控制数据库丢失之后）会阻止卸载，应用中暂时没有补救办法。
- 资源管理器中的缩略图与锁定或共享叠加图标需要上游的 Shell 扩展，而它未构建。
- 尚未验证：已发布的安装包与可执行文件对服务器的运行（覆盖安装真实的 0.1.0、卸载程序对按需目录的释放）；资源管理器中 SyncD 自己的导航窗格条目与图标；
  Cloud Files 不可用时的行为；真实守护进程中 1 万与 10 万个文件的转换耗时（[平台说明](platform-notes.md#011-的后续证据)）。
- 0.1.0 的其他限制依然存在。

版本，2026-11-14 核对，没有变化：Nextcloud Desktop v35.0.3（引擎），测试用 Nextcloud 服务器 35.0.3 与 34.0.6；
Go 1.27.4；MyGo v0.9.0。Qt 和 OpenSSL 以 `build-lock.json` 的记录为准。

## 0.1.0

首个发行版：Windows 11 测试版，每个架构（x64 和原生 ARM64）一个当前用户安装包。

- **一个账号，多个地址。** 每个账号可以有同一服务器的多个受信任地址（互联网、家庭网络、VPN）。
  地址只有在其服务器、TLS 证书和目录命名空间都验证通过后才为账号服务。SyncD 自动选择地址，或保持你固定的地址；
  只在两次同步周期之间切换，账号的所有目录一起切换。登录或证书失败会阻止该地址，任何评分都不能越过。
- **Nextcloud Desktop 引擎。** 发现、协调、传播和 journal 都来自上游 Nextcloud Desktop，加上 19 个小补丁，
  运行在 SyncD 中，SyncD 是当前用户的后台进程。界面（Go 和 MyGo）通过本地命名管道与其通信，协议 1.10；
  关闭窗口从不停止同步。
- **文件安全。** 删除保护会把大量或异常的删除留给你确认。未确认的上传、移动或删除通过重新发现恢复；
  服务器不可达或目录无法读取时绝不当作空。传输中被打断的修改会保留服务器上的上一版本（修改以分块上传发送）。
  移动因网络失败的本地改名保持新名字，之后再次发送。
- **多个账号**，每个账号多个目录；通过浏览器登录；应用密码的续期与撤销；服务器已满或响应慢时分别如实报告。
- **界面：**概览、账号与目录、网络、含删除确认的活动、设置、托盘及其浮出面板；英文和简体中文。
- **安装与更新：**当前用户安装包，可原地升级，并检查每个二进制文件与架构相符。应用内更新只安装用项目更新密钥签名的
  压缩包；在设置中打开之前保持关闭。

已知限制：

- 按需文件已构建但未提供（`virtualFiles`）。
- 安装包没有 Authenticode 签名，因此首次安装时 Windows SmartScreen 会警告。
- 只在一台原生 ARM64 机器上测试。x64 二进制在该机器上以模拟方式通过了测试；x64 安装包未在 x64 硬件上运行过。
- 未覆盖：真实睡眠与恢复（仅模拟）、24 小时运行（以 1 小时加速长时间测试代替）、严格的 VPN 出口、
  第二个 Windows 会话或用户、端到端加密目录、驱动器号被其他卷复用、手工恢复的 journal。
  开机自启在发布后检查。
- 删除保护按单个同步周期计数：分散在多个周期中的删除不会累加。
- 安全阻止（证书改变、服务器不是预期的那一个）会持续到 SyncD 重启。
- 在测试机器上，多个进程同时写入 Windows 凭据管理器时会丢失更新。SyncD 自己的写入不会重叠，但另一个程序恰好同时写入时，
  可能使某个账号要求你重新登录。
- 一次 20 分钟测试运行中 SyncD 出现过一次访问冲突，此后约五小时的运行未能复现，原因未明。
- 本版本不包含 macOS。

版本：Nextcloud Desktop v35.0.3（引擎），针对 Nextcloud 服务器 35.0.3、35.0.2 及上一主版本 34.0.6 测试；
Go 1.27.4；MyGo v0.9.0；Qt 6.12.0；OpenSSL 3.6.5。
