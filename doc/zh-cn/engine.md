# 引擎集成

## 所有权

能力安装工作现同时审计上游 setter 和响应格式。为无头运行创建的 `Account::create(false)`
在安装能力后也必须保持无头：否则上游 `setCapabilities` 会重新创建用户状态服务，并可
启用推送/状态报告。新的窄上游回归在修复前于 `!hasUserStatus` 断言失败。补丁 0015 在能力
更新时保留无头生命周期；其构建及集成仍在进行。运行时能力安装必须使用来自认可 origin
且已验证的元数据，保持不支持的后台功能禁用，并保留既有请求 origin 和 journal 门槛。
此检查点不宣称现代分块上传或可移植跨 origin 恢复验收通过。
适配器在启动 libsync 前，每个运行时 epoch 加载一次认可 origin 的能力元数据，验证 OCS
封装/版本及现代 DAV 分块声明，仅提供同步相关能力组。不导入用户状态、推送、遥测、主题
或服务器管理的桌面配置。缓存元数据属于该不可变绑定；重新绑定必须重新加载。

B09–B12 网络集成工作将 Windows 网卡/地址/路由通知及恢复事件连接到绑定 generation 的
只读健康检查。同时轮询 DNS 配置，不记录接口名称或地址。事件立即使证据失效，评估去抖
2–10 秒。健康检查序列总预算四秒，每账号最多两个、全局四个；全量 UID/能力/全部根检查
独立执行，且激活前必须通过。普通健康检查不读写用户内容。未知路由成本/偏好保持中立；
不声明严格 VPN 出口及计费网络强制约束能力。
网卡/地址/路由回调仅设置原子通知位，通过 `CancelMibChangeNotify2` 排空。休眠/恢复使用
控制线程上的进程局部仅消息窗口，注销后同步销毁。不创建可见窗口、Shell 入口或系统
设置；电源回调不能保留已释放的 Qt/控制对象。
探测评估在嵌套 Qt 元数据请求期间持有自有端点标识，并在返回后重新取得选择条目。移除
地址不能留下悬空映射键或授权下一个携带凭据的请求：全量验证各步骤之间、轻量探测认证
步骤之前均重新检查许可及冻结根。真实只读移除回归在修复前复现 ARM64 访问冲突
`0xC0000005`；父进程仍完成借用原生凭据的清理。

协议 1.6 / Control schema 7 工作增加持久端点策略。`auto` 启用守护进程提案；`fixed` 预留
切换，直至重新核对成功才替换旧策略，包括暂停根恢复后的核对。请求目标与实际绑定分别
投影。无策略的既有配置保持实际端点固定，直至显式更改。故障切换请求上游取消，排空预算
120 秒；健康优化仍在 30 秒后延后，不打断健康传输。验证及发布复核网络、策略及绑定
revision。准备失败仅可经过新验证和新分配的 epoch 恢复原绑定。恢复成功不将旧失败回执
改成成功。重复失败目标等待新的独立断路恢复样本，不在坏地址间反复轮转。安全隔离跨重启
保留，仅显式验证可解除。此连接路径的实现及验收进行中，不构成能力声明。

持久化切换工作进行中：Control schema 5 将切换准备与已提交的端点绑定分开记录。目标 epoch
在 Control 事务内单调分配；提交绑定后保持重新核对门槛，直至每个注册目录均获得成功的新
epoch 结果。重启将未完成意图改为 `blocked`，不回滚绑定或重放文件请求。此存储层本身
不授权运行时激活。
引擎完成携带不可变绑定 epoch，包括预检失败和取消。Control 在发布状态或删除决定前
忽略旧绑定或重启阻塞意图的结果。因此，迟到的成功完成不能将阻塞目录显示为正常。

接通的手动切换路径（B11/B12，验收中）在关闭账号准入前预留意图和回执。它等待当前周期
自然结束，最长 30 秒，退役所有旧账号/管理器/回复，重新验证目标 UID 及全部映射根，再在
准入仍关闭时提交绑定。运行时重新绑定保留 journal 和根租约。只有匹配的新 epoch 成功周期
才消耗重新核对成员；暂停目录保持待处理，直至用户恢复。退役后的失败留下持久阻塞，绝不
隐式恢复。`endpoints.requestSwitch` 返回运行中回执，通过 `operations.get` 观察完成。
自动策略激活及完整故障恢复仍未完成。

中断切换的启动恢复采用最后已提交端点，而非未提交目标。重新取得原始根租约后，它预留
新的内部操作/epoch，并运行相同的重新验证与核对路径。被中断回执保持失败。此前的硬验证
失败不会自动重试。同 origin 恢复将已有传输行交给上游恢复。跨 origin 重新绑定仅允许已
审计的带非空 ETag 的相对下载状态、校验和非空的单 PUT 结果不明状态，以及校验和非空的
分块 v2 会话；轮询 URL 和旧版 v1 分块索引仍被阻塞。准入绝不编辑这些行。
发布前验证还要求 OCS files 能力映射以及可读（`G`）的 DAV 用户根/映射根。不据此推断写入
权限：上游发现仍执行每个项目的实际权限。全部退役本地根及只读恢复上下文在 Control 提交
前检查，重新绑定时再次检查。TLS/身份失败将备用地址的验证证据标为拒绝。

目录连接工作进行中：Control schema 3 持久化目录 ID、本地卷/文件身份、远端根身份、
与端点无关的 journal 路径及目录独立暂停。检查 token 短期有效，添加时重新验证；移除映射
保留用户文件及 journal。认证 DAV 元数据读取必须留在已批准的 HTTPS 安装边界内，不跟随
重定向。运行时恢复必须在调度前重新验证根。这些改动须经集中守护进程验收后才能声明支持。

B05 引入围绕上游 `SyncEngine` 的进程内适配器，而非 CLI 子进程。
适配器拥有一个不可变账号运行时、显式 journal 路径和一个周期。所有 Qt 调用留在控制线程。
凭据从已经保留的原生安全存储引用读取；不使用上游按 URL 派生的钥匙串持久化。
网络边界强制手动重定向，并在附加凭据前检查已批准的安装路径。

## 完成与安全

健康探测失败立即使此前成功选择证据失效；打开断路仍要求三个独立传输故障。业务 TLS/
身份/认证失败不依赖取得健康探测票据：即使探测占用或断路已打开，也使未结束证据失效。
安全隔离独立持久化，迟到的成功探测不能解除它。集成回归在此修复前复现隔离丢失
（INV-04/06/14）。

只有失败的探测才会阻断活动端点。断路器仍在恢复（半开）期间，成功的探测是恢复证据，绝不
阻断账号，也不会使刚刚激活该端点的切换失败；此时失败的探测仍会阻断。在此规则之前，手动
切换到恢复中的地址会先通过完整验证，随后被它自己的成功探测以 `NETWORK_UNAVAILABLE` 判为
失败。真实活动传输夹具发现了该问题，集成回归可复现（INV-06/14）。

真实重新绑定验收发现，普通文件下载成功后仍留下恢复记录：上游
`PropagateDownloadFile::updateMetadata` 删除了空的加密文件名键，而非写入记录时使用的
普通路径。补丁 0014 使用传输开始时 `setDownloadInfo` 的同一文件键。ARM64 下载回归
已证明成功后清理且未完成传输状态仍保留，随后通过复用原 journal 的真实备用地址重新绑定。
十四补丁上游套件已在 ARM64 和模拟 x64 通过；切换门槛继续失败关闭。

独立切换守卫将旧运行时排空与新 epoch 重新核对分开（§9.3）。结果不明的远端写入不要求
在提交已验证目标前恢复；每个冻结目录改为在提交后保持待核对状态。只有匹配新 epoch 的完成
才能清除其恢复条目。取消准备不能清除已提交的恢复工作。

退役运行时重新绑定前，只读 journal 检查拒绝不可读/损坏的 schema。跨 origin 恢复允许
带非空 ETag 的相对下载路径/临时路径，以及单 PUT 上传行（`transferid=0`、`chunk=0`、
大小非负、mtime 为正、校验和非空）。Desktop v35.0.3 的下载路径比较发现 ETag、回复 ETag、
范围及内容长度；单 PUT 发现比较持久校验和后才解释结果不明的写入。适配器在传播前使用
原 journal 强制上游远程重新发现。
分块 v2 会话行（`transferid` 非零、`chunk=0`，大小、mtime 和校验和规则相同）同样被准入。
它不保存任何地址：上游相对当前账号定位会话，在目标上先列出会话再发送任何内容，从最后一个
完整分块之后续传，并在发现阶段按校验和接纳服务器已落盘的最终 MOVE。补丁 0016 为换地址后
的这两种情形增加了上游回归。在针对服务器 35.0.2 的真实运行中，112 MiB 上传在第二个分块中
被打断后，在另一个 origin 上续传且未重发第一个 100 MiB 分块；使用此前的闸门时，同一运行
无法离开已故障的地址。
任何待处理轮询 URL、旧版 v1 分块索引或不支持/畸形传输上下文
报告为 `RESUME_CONTEXT_UNSUPPORTED`；绝不为强行切换而删除或改写它。不存在的 journal
没有已有恢复上下文。同 origin 恢复仍由上游负责。真实的最终 MOVE 响应被扣留、已有条目的
结果不明 MOVE/DELETE 以及超过 4 GiB 的文件尚未验收。
相对恢复路径还拒绝以点/空格结尾的路径分量及 Windows 通配符/控制字符，避免 Win32
规范化重新解释声称位于子目录的路径。在此边界修复前，只读回归未拒绝 `.. /outside`
及其嵌套形式；检查仍不修改 journal 或临时文件。

恢复必须保留未通过 SQLite 完整性检查的 journal。补丁 0013 使上游 SQL 包装层的自动
数据库重建可选择关闭，并专门为 journal 禁用它。损坏 journal 回归要求重复打开失败后仍保留
完全相同的原始字节。这不修复 journal，也不授权完整重新同步。真实损坏字节保留及提交
失败测试已通过；各架构证据见[平台说明](platform-notes.md)。

切换准备要求可观察的 journal 提交结果。补丁 0011 为上游 journal 增加粘滞的
`hasCommitError()` 状态：SQLite 提交失败在该对象关闭/重开后仍可见，后续成功操作也不会
清除它。适配器必须在该标记置位时报告 `JOURNAL_ERROR`，不能报告成功。回归使用 SQLite
提交钩子拒绝真实事务，验证回滚，并检查关闭不能掩盖失败。
记录中的十三补丁构建已通过两个架构的上游套件；详见平台说明。

`RequestLifetime` 现已观察活动与仍被保留的回复，统计未确认的修改性请求结果，包括未发出
`finished` 就销毁的情况。后续成功请求不能消除这种不确定性。引擎适配器还统计存活网络管理器，
将被拒 origin、TLS 失败和 HTTP 401 与一般周期错误区分。空闲退役永久关闭绑定，检查 journal
提交状态并排空延迟的账号/网络销毁，同时保留根租约。退出等待这些可观察的生命周期；若旧网络
资源不能排空，则在有界期限后执行致命停止。这些观察本身不构成远端重新核对的证明。
退役审计暴露了上游所有权环：`Account::create()` 将自身强引用赋给
`ClientSideEncryption::_account`。适配器从不初始化 E2EE，现仅在引擎销毁后、释放账号前
清除该辅助对象的账号引用。真实引擎夹具在退出回调检查存活管理器和回复均为零；仅回复单元
测试不能验证这种账号所有权行为。
进一步跟踪发现，`setSharedThis()` 还会启动 `OcsUserStatusConnector`，后者持有第二个账号
强引用。补丁 0012 使此交互服务在账号创建时可选择关闭；SyncD 使用无界面的形式。
上游客户端的默认行为仍启用该服务。其定向回归在清除未启用 E2EE 的引用后观察账号实际销毁；
真实适配器夹具另行要求账号、管理器和回复计数均归零。

成功周期持久化时，将 Qt 的 null 原因字符串转换为空 SQL 文本，满足 schema 的非空约束。
双目录守护进程夹具同时检查终态和已传输字节，因此传输完成但调度停滞仍会导致验收失败。
若完成事务本身失败，SyncD 关闭任务准入并在引擎销毁后退出，不会静默保持存活且永久
`syncing` 的状态投影。UI 断线后将状态标为不可用。重启重新验证根并使用现有 journal
重新发现，绝不伪造成功回执，也不通过修复 journal 来绕过 Control DB 失败。

引擎 `finished` 信号仅启动销毁流程。适配器销毁引擎并排空其延迟 discovery 销毁后，
才释放 journal 或报告完成。这本身不构成端点切换静止性的证明。补丁 0010 允许在创建传播器前
中止。删除提案按旧 journal 基线分别统计两侧后代；限时单次批准要求重新发现的摘要匹配。
目录所有权、传播安全和真实守护进程完整验收接通并通过前，
完整同步能力保持禁用。

## 调度

目录挂接保留稳定的凭据、journal 和根目录阻塞原因。遇到意外内部错误或无法持久化挂接
错误时，停止引擎准入，不改写 journal。普通目录投影独立于用户暂停公开脱敏 `reasonCode`；
界面不能将该技术代码直接作为面向用户的文案显示。

预检网络及根暂时不可用错误保留待处理任务，并在退避后重试，不会永久阻塞目录。
TLS、身份、凭据、journal 和不支持模式的失败仍是独立安全阻塞。用户暂停和删除决策
在重试期间保持有效。
硬阻塞现保留各自原因，而非共用安全位。验证过的凭据轮换仅在准入关闭时清除
`AUTH_REQUIRED`/`CREDENTIALS_LOCKED`，随后以同 origin 的新 epoch 重新加载登录名和稳定
凭据引用。它不能清除 TLS、根或 journal 失败。

元数据响应区分权限拒绝（403）、远程锁定（423）及服务器限流（429）。所需 DAV 属性
不可用不是命名空间不同的证据。内部 `MetadataError.retryAfterMs` 未指定时为零，有界
相对期限下限为 60 秒，有效期限超过七天或溢出时为 `-1`；最后一种情况不能变成提前
自动重试。仅解析 HTTP-date 时使用 UTC，之后通过单调时钟调度。账号级消费方执行仍在
集成中，尚不构成验收声明。

后续在 Control schema 8 增加持久账号限流存储，在运行时激活前恢复。进程重启、用户
唤醒或不同的已认可 origin 都不能缩短服务器要求的延迟。有限期限必须保守地重新建立
为单调时钟期限；无限期阻塞跨重启保留。持久化失败必须关闭准入，不能确认随后会丢失的
限流。实时引擎和重新认证消费方仍在集成中；尚不宣称完整 N18 验收。

串行队列使用调用者提供的单调时间。每个目录维护独立阻塞原因、dirty 和捕获代次、
合并的待处理原因集合，以及有界本地变化去抖。成功完成仅确认捕获的代次；失败或取消
的工作仍待处理。账号和目录轮换防止立即跟随任务独占引擎。
恢复一种暂停不会清除其他阻塞。`EngineRuntime` 将队列连接到适配器，按 60 秒 ±20%
抖动轮询、请求每日完整核对，并以有界指数退避保留失败代次。退出冻结任务准入并等待
活动周期销毁。递归监听使用 Windows 重叠 I/O 子树订阅，覆盖新创建的目录。
通知仅标记待处理变化，发现仍是权威来源。溢出或通知丢失请求完整核对，并保留轮询兜底。
监听句柄在销毁前取消并排空；回调留在控制线程，不能覆盖暂停或阻塞。
持久 Control/IPC 目录登记已接通。

## 本地根租约

`RootLease` 仅接受普通本地固定 NTFS 目录，并拒绝重解析点祖先以及根目录或祖先中的既有
上游 journal。原生卷/文件身份、按用户划分的全局准入互斥量、精确根互斥量和共享祖先
存在事件，共同排除同一 Windows 用户跨进程、跨配置的相同或嵌套 SyncD 映射。准入互斥量
仅覆盖登记过程；无关的兄弟根仍可并行。根目录和祖先目录句柄拒绝删除共享，每轮同步前
重新检查身份。隐藏文件系统祖先的盘符别名会被拒绝。所有权由内核句柄承载，不使用持久
记录或 PID；释放句柄和进程终止都会撤销所有权，内核对象操作失败时保守拒绝。这不检测
官方客户端之后进行的登记。递归预检和传播前扫描继续拒绝树内的重解析点、脱机/召回对象、
不可读目录及上游 journal。

## 构建与验收

启动辅助模块先取得配置档案锁，再读取原子写入的崩溃记录。十分钟内观测到六次非正常退出
