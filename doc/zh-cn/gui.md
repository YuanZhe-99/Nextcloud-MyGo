# 界面

界面是一个原生 MyGo 应用（`cmd/nextcloud-mygo`、`internal/gui`），面向使用 Nextcloud MyGo 的人，按 `design/`
中的设计稿实现。它自己不保存任何同步状态：账号、目录、地址和待决事项归 SyncD 所有；界面显示 SyncD 报告的快照，
并通过 `internal/syncd.Remote` 向它发送命令（协议 1.9，见 [IPC](ipc.md)）。默认连接配套的 SyncD 可执行文件；
`NEXTCLOUD_MYGO_MOCK=1` 显式选择 `syncd.Mock`，它注明其示例数据、声明自己模拟的能力，并且不会更改本机上的任何内容。

## 线程与状态

`gui.App` 的每个字段只在主线程读写。视图在主线程运行；发给 SyncD 的命令在单独的 goroutine 中执行（`App.do`），
结果经 `App.later` 交回主线程，并重绘窗口和托盘。命令返回前，对应按钮保持禁用；失败以文字提示（toast）显示，
文字依据 SyncD 的稳定原因代码（reason code）给出，从不显示代码本身。已被接受的命令不会显示为已完成：结果由下一个快照显示。
界面自己的设置保存在 `%AppData%\Nextcloud-MyGo` 的 `gui.json` 中，原子写入；与同步有关的内容都不放在这里。

## 连接与能力

- **未知不等于空。** 在收到第一个快照之前，以及 SyncD 在没有其状态的情况下运行时（`stateAvailable` 为 false：
  退避、诊断、已停止或数据库不可用），窗口显示一张状态卡片，提供“诊断”和“设置”，而不是各页面或首次设置。
  SyncD 没有发送的列表视为未知：不显示“还没有目录”或“还没有记录”。
- **断开连接不等于当前状态。** 管道断开后，最后已知的列表保留在一条说明此情况的横幅下；在 SyncD 恢复之前命令都被禁用，
  也不会有任何内容显示为正常。
- **能力决定功能。** 登录需要 `login`。`fullSync` 为 false 时，添加目录前会先说明文件同步仍在验证中，任何状态都不会显示为绿色：
  SyncD 报告为已是最新的目录显示为“上次同步已完成”。`endpointAutoSwitch` 为 false 时不提供“自动”；每个账号使用选定的一个地址。添加更多账号需要 `multiAccount`
  （第一个账号不需要）。只有在有 `virtualFiles` 时才提供“完整文件”或“按需文件”。
- **重新登录。** 账号是否需要重新登录以它的 `auth` 为准：`needsSignIn`（保存的登录信息在本机上无法使用，或续期正在等待浏览器）
  或 `revoked`（服务器拒绝了应用密码），各用自己的文字说明。只有不发送 `auth` 的 1.9 之前的守护进程，才根据账号已退出登录或某个目录
  报告 `AUTH_REQUIRED` 来推断。
- **服务器已满。** 报告 `REMOTE_QUOTA_EXCEEDED` 的目录已完成它的同步周期，但上传被拒绝：它显示为“服务器存储空间已满”，
  它的账号得到一条说明其含义的提示，整体状态为需要你处理。

## 主窗口

- **标题栏：** 由视图绘制：标志、名称、拖动窗口的区域，以及 Windows 11 的标题栏按钮。
- **侧栏：** 各个账号，每个显示它的服务器或“需要重新登录”（最多四个，其余只显示数量；每个都打开“账号与目录”）、四个页面
  （“活动”上显示待处理数量）、设置，以及用圆点和文字表示的整体状态和所选账号正在使用的地址（打开“网络”）。整体状态取第一个成立的：
  未知、已暂停、需要你处理（删除确认、需要重新登录的账号、服务器已满、等待中或失败的目录）、正在同步、离线、
  上次同步已完成（没有 `fullSync` 时）、已是最新。
- **概览：** 暂停同步 / 恢复同步和立即检查；同步当前在做什么，显示阶段和已完成的文件数（`phase`、`filesDone`），而不是编造的总量，
  每个正在同步的目录卡片上也显示；所选账号正在使用的地址及原因；所有需要处理的事项，各带一个处理按钮（服务器已满没有按钮：
  只有在服务器上释放空间才有用）；目录。
- **账号与目录：** 添加账号；每个账号的登录状态、添加目录或在浏览器中登录（等待期间改为“再次打开浏览器”和“取消”），菜单中的
  “重新登录”和“移除此账号”；它的目录：模式（有 `virtualFiles` 或目录为按需文件时）、路径、状态、用文字说明的原因，以及打开、
  暂停或恢复、查看，菜单中的立即检查和停止同步。移除目录或账号前会先询问，并说明两边的文件都会保留；移除账号只是一次
  `accounts.remove`，它会在正在运行的周期结束后自行停止该账号的目录。
- **网络：** 自动或始终使用一个地址（仅在有 `endpointAutoSwitch` 时）；账号的各个地址，正在使用的排在最前、核验失败的排在最后，
  每个都显示它通往哪里（名称没有说明时显示其类型）、两步信任（已认可、已核验为同一服务器）、用文字说明的被阻止原因（证书、
  另一台服务器、从未允许的地址、需要登录、其他网络；正在核验时由信任步骤说明）、响应速度（`latencyMs`），以及立即核验、使用这个、
  待完成的切换和移除此地址；选用当前地址的原因（`network.why`：已核验、更快并给出两边的响应时间、稳定、你的选择、加入的网络、
  其他地址无响应、推迟的切换），以及上次切换的时间和原因；最近的切换。切换以请求方式提出（`endpoints.setPolicy`），
  在 SyncD 到达安全点之前显示为待完成。
- **活动：** 每个删除确认（多少文件、每个方向及其数量、SyncD 列出的分组及其文件数、提案何时过期；“稍后决定”在前，然后是
  “打开文件夹”，“允许删除”只有在第二次询问后才执行；没有其他方式回应删除确认）；冲突，每个用“标记为已解决”关闭
  （`resolved`，两份副本都保留）；其他需要处理的事项；最近的记录，可筛选。

## 对话框

- **添加地址：** 第 1 步只查看地址，并选择它通往哪里（互联网、家庭网络、VPN；这从不影响信任），不发送任何凭据；第 2 步显示证书和服务器信息，并请用户明确授权；第 3 步核验
  由 SyncD 在认可后完成。证书无效的地址不能被认可；被拒绝的地址会说明原因。
- **询问：** 移除、停止和允许删除都使用警告框，“取消”在前。

## 首次设置

在 SyncD 报告没有账号时代替各页面显示，“添加账号”时也会显示：你的服务器、登录（在浏览器中完成 Login Flow v2；界面永远看不到密码；已添加过的账号会直接说明，设置停留在“你的服务器”）、
目录（加密目录不能选择；有 `virtualFiles` 时为选定的目录选择“完整文件”或“按需文件”，每个目录在整个生命周期内固定；尚不存在的本地目录
由 SyncD 创建）、开始（“登录 Windows 时启动”和通知，默认都开启；可选添加其他地址）。点“开始同步”之前不会同步任何内容。“添加目录”会为已有账号打开“目录”这一步。

## 设置

设置以覆盖在变暗窗口上的面板打开（侧栏齿轮）：左边是搜索和各页面（常规、通知、同步与存储、网络、关于与更新、诊断），
右边是页面，由若干分区的行组成，每行是图标块、标题和一句说明，以及它的控件。

| 页面 | 设置 |
|---|---|
| 常规 | 语言（跟随 Windows、English、简体中文）、外观、登录时启动、在托盘中启动、关闭按钮、添加另一个账号 |
| 通知 | 需要确认的删除、需要重新登录、冲突、更新 |
| 同步与存储 | 暂停所有目录；删除保护，始终开启 |
| 网络 | 指向“网络”页面的链接 |
| 关于与更新 | 更新、每天检查、自动安装（从不、空闲时、每天 03:00）、版本（含 SyncD 版本和协议）、源代码、开源许可 |
| 诊断 | SyncD 的启动报告（之前的版本和 schema、当前 schema、自检及其原因代码）和管道上次断开的原因（`Remote.Disconnect`），只在这里显示；SyncD 的运行时读数（`diagnostics.snapshot`：版本、启动、epoch、计数）；SyncD 生成的支持包（`diagnostics.export`）、其路径、打开文件夹和复制路径 |

## 托盘与关闭

- 单击托盘图标打开浮出面板（状态、需要处理的事项、目录、打开、暂停、立即检查、只关闭窗口、退出并停止同步）；右键单击以菜单形式
  提供相同的操作。两者调用的都是窗口所用的同一组方法。
- 关闭按钮默认把应用留在托盘中（第一次会提示），也可以在“常规”中改为关闭窗口；两种方式下 SyncD 都继续同步。只有“退出并停止同步”
  会停止它（`daemon.shutdown`）；如果 SyncD 没有停止，界面会保留并说明这一点。
- 主窗口只在显示时存在。登录时启动且开启“在托盘中启动”时，应用只显示托盘图标。再次启动只会唤起已在运行的窗口。

## 更新

只有签名的发布版才能自我更新（`mygo.Updater.Enabled`）；其他版本会说明这一点，其更新控件处于禁用状态。开启时每天检查一次。
安装前先请 SyncD 到达安全点（`PrepareUpdate`）；被拒绝时安装会推迟，并说明原因：有删除在等用户确认（`DECISION_PENDING`，
提供“查看”），或同步尚未到达安全点（`QUIESCE_STALLED`），两者通过 `syncd.ReasonOf` 区分。自动安装在电脑空闲 15 分钟后
或 03:00 这一小时内进行，取决于所选方式；失败过一次的安装在同一次运行中不再重试。

## 语言

字符串位于 `locales/en.json`（源）和 `locales/zh-Hans.json`；`go tool mygo
generate` 生成 `locales/catalog_gen.go`。繁体中文和日文随后补充。

## 测试

`go test ./internal/gui` 以两种外观、两种语言渲染每个页面和设置页面；检查删除确认（“稍后决定”保留提案，允许删除需要询问两次）、
设置中的暂停，以及“恢复同步”不会撤销单个目录自己的暂停；检查未知状态既不显示为空也不显示为正常、SyncD 的真实能力
（没有“自动”、没有绿色、有文件同步说明）、密码被拒绝时的重新登录，以及每个协议原因代码都有对应文字。协议 1.9 的状态以表驱动方式测试（`protocol19_test.go`）：
每种账号 `auth`、侧栏中的多个账号、`multiAccount`、重复账号、一次命令移除账号、阶段与服务器已满、有无 `virtualFiles` 时的目录模式、
每种被阻止原因、选用当前地址的原因、多个删除确认和关闭冲突、更新的推迟，以及启动报告只在诊断中显示。Mock 的示例数据展示了上述每种状态。设置 `SYNCD_TEST_EXE` 后，
`TestRealDaemonInterface` 通过真实管道让界面驱动编译好的 SyncD（新 profile 显示首次设置、暂停、诊断及其支持包、界面关闭后
SyncD 继续运行；设置 `NEXTCLOUD_TEST_URL` 时，还会启动并取消一次浏览器登录）。设置 `SCREENSHOT_DIR` 后，它会把每个窗口写成 PNG，
用于与 `design/` 对照。
