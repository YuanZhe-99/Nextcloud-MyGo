# 账号与登录

## 所有权与存储

SyncD 将 Login Flow v2 token 保存在内存中，应用密码仅写入 Windows 凭据管理器。
写入秘密前，持久的 `creating` 账号先保留 UUID 和凭据引用。只有验证用户 UID 和 DAV
集合根身份后才可转为就绪。重启时清理中断的 creating 账号；凭据清理失败时停止启动，
而不是遗忘孤儿凭据。界面与 Control DB 均不接收应用密码。

重新认证工作（B04/B08/B12）使用 Control schema 6 和协议 1.5。持久会话预留两个派生的
原生凭据库槽位：候选及旧凭据。现有账号、origin 许可、目录 ID、根身份、journal 和用户
暂停保持不变。候选凭据必须匹配原 UID、账号根及全部映射根，才可安装。替换稳定凭据槽位
前，先关闭引擎准入并排空；以同端点的新 epoch 重新加载运行时。
替换前备份旧凭据并提交 `prepared`。在该阶段重启会恢复旧凭据；已提交 `installed` 阶段则
保留验证过的新凭据。两条路径都不猜测中断写入由哪个秘密胜出。候选/备份槽位在清理成功
前保持持久预留。通过认可的规范 origin 尽力撤销旧应用密码；未确认撤销会明确警告，而非
静默成功。
回滚先提交 `discarding`，再删除备份，因此清理中崩溃不会留下缺少恢复来源的 `prepared`。
此前缺失的凭据恢复为缺失，不凭空生成。候选与旧密码相同时，绝不将它当作被替代凭据撤销。
安装后本地根不可用时保持其运行时阻塞，不撤回已验证凭据或导致反复启动失败。重新认证仅
可清除凭据专属调度阻塞；用户暂停、TLS、根、journal 和删除安全门槛保持独立。
等待或回滚中的重新认证将未暂停目录投影为 `waitingSignIn`，不保留过期绿色状态。全局及
单目录用户暂停仍显示为暂停。
嵌套的 Qt 元数据验证保留其原登录会话，直至调用返回。取消并启动替代会话不能销毁仍在使用
的对象，也不能让旧结果使新会话失败。独立只读生命周期夹具使用借用凭据，并由父进程负责
原生凭据键清理，包括回归使子进程崩溃的情形；它绝不撤销这些借用凭据。

## 多个账号与移除

自协议 1.9 起，一个守护进程可以持有多个账号，位于同一台或多台服务器。每个账号有自己的端点、策略、
切换意图、绑定与 epoch（都按账号存储），因此一个账号的切换只让该账号的目录静止。一个账号就是一台服务器上
的一个用户：新登录验证后的 UID 与 DAV 根身份与某个就绪账号相同时，无论使用哪个地址，都被拒绝并返回
`ACCOUNT_EXISTS`，其取得的密码像任何被拒绝的登录一样被撤销（借用的验收凭据从不撤销）。检查在命名空间
证明之后进行，因此同一用户的两个并发登录不会都成为账号。

`accounts.remove` 对任何就绪账号都会被接受。账号立即变为 `removing`，之后的每一步和每个回调都会检查
（`a.state='ready'`）：取消其登录与续期，等待进行中的地址检查结束，关闭准入（`accountRemoving`），
请求运行中的周期或按需下载停止并等待其结束。随后移除其运行时，结束每个按需注册（两分钟内无法结束的注册
使移除失败并给出原因，账号保留，引擎重新挂接；已不存在的根不含占位符，直接跳过），未完成切换的回执以
`CANCELLED` 失败，切换、续期与映射记录连同预留的续期凭据库槽位一起删除，然后执行原有的撤销。本地文件与
引擎日志数据库保留。移除期间重启时，恢复流程以同样方式完成移除，不发送服务器请求；此时移除报告撤销未确认。
续期中尚未撤销的旧密码不会因移除而被撤销。

快照中的 `account.auth`：服务器拒绝了存储的应用密码时（某个目录或当前地址报告 `AUTH_REQUIRED`）为
`revoked`；凭据无法在本机使用（`CREDENTIALS_LOCKED`）或续期正在等待浏览器时为 `needsSignIn`；否则为
`signedIn`。

## 登录边界

输入默认补全 HTTPS。拒绝包含用户信息、查询、片段或模糊路径的 URL。
浏览器与轮询地址必须留在明确选择的 origin 和安装路径内。登录/验证客户端不跟随重定向，
始终启用 TLS 验证。每个登录会话拥有自己的网络管理器。不持久化轮询 token 或浏览器登录
地址。取消和过期会中止在途工作，并使迟到的完成事件失效。

重新认证元数据、实时回复及凭据清理遵守同一持久账号级 Retry-After 门槛；备用 origin 和
守护进程重启不能绕过。`LoginFlow` 的每个请求都按共享元数据规则区分 HTTP 403、423 和 429
（`PERMISSION_DENIED`、`REMOTE_LOCKED`、`SERVER_THROTTLED`），绝不当作认证或身份结论。
确认的 429 先关闭流程的请求闸门，再通过账号限流提交，之后才可能发送其他请求；提交失败时
流程不再发送任何请求。Retry-After 沿用共享边界：至少 60 秒，至多七天，更长的有效期限表示
不自动重试。

会话在 20 分钟单调时间内有效，任何服务器延迟都不会延长它。仅当延迟在会话内结束时才恢复
轮询；否则会话以被限流或被锁定失败。已过期或取消的会话绝不接受候选。撤销流程自己取得的
密码与会话成功分开：服务器的有界延迟阻止撤销期间，流程停留在 `discarding`，保留凭据库
槽位和持久预留，延迟结束后发送 DELETE，即使会话已过期。被服务器以 429 或 423 拒绝的
DELETE 会重试；结果未知（传输失败、超时）的 DELETE 绝不重放，并以
`APP_PASSWORD_REVOCATION_UNCONFIRMED` 结束，403 和不自动重试的延迟同样如此。

新登录被搁置的撤销在守护进程重启后依然有效。当 DELETE 只是被服务器延迟时，Control schema 9
为已预留的账号保留一行 `held_revocations`：该密码由本守护进程取得，且没有 DELETE 在途。任何
DELETE 发出之前先删除该行；无法删除时不发送 DELETE。重启后的守护进程若同时找到该行和密码，
则保留凭据库槽位和预留，恢复账号限流，至少等待共享的 60 秒下限以及已保存延迟的剩余部分，
然后只发送一次 DELETE。被中断的登录自重启起即为 `LOGIN_SESSION_EXPIRED`；只有未得到应答或
被拒绝的 DELETE，或不自动重试的延迟，才会把它改为 `APP_PASSWORD_REVOCATION_UNCONFIRMED`。
没有该行时，进程结束时可能有 DELETE 在途，因此不再发送任何请求，登录报告为未确认。在结果
出来之前，预留继续占用唯一的账号位置，与创建它的进程中的行为相同。重新认证的候选密码不在
此范围内：其撤销被搁置期间重启仍报告 `APP_PASSWORD_REVOCATION_UNCONFIRMED`，因为回滚会连同
恢复的凭据一起移除候选槽位。这些规则由手动时钟上的脚本化传输回归和 Control 重启回归覆盖。
在隔离的服务器 35.0.2 上，重启后的 Control 把真实签发的应用密码的被搁置 DELETE 只发送了
一次，服务器予以确认并随后拒绝该密码，原生 ARM64 和模拟 x64 均如此；真实服务器的 429 仍未
验证。

## IPC 与能力

协议 1.1 新增 `accounts.login.status(loginSessionId)`，区分登录会话身份与启动它的操作。
启动通过常规操作结果返回会话 ID、浏览器地址和到期时间。状态返回会话状态，且仅在账号
提交后返回账号 ID。守护进程重启使未完成的登录操作过期。目录同步仍是独立能力。
协议 1.5 实现 `accounts.reauthenticate(accountId, expectedRevision, operationKey)`，使用
相同的浏览器会话结果及 `accounts.login.status` 轮询。等待/回滚会话在重启时过期，不移除
账号；已安装替换继续本地清理。最近一次已完成重新认证的状态跨重启保留。成功状态可携带
`APP_PASSWORD_REVOCATION_UNCONFIRMED`：Go `WaitLogin` 此时同时返回保留的账号 ID 和
`ErrCredentialCleanup`。

## 验证范围

2026-11-05，原生 ARM64 和模拟运行的 x64 登录/核心契约测试通过。迁移后的
`tools/test-login.ps1` 在原生 ARM64 上针对服务器 35.0.2 通过：真实 Login Flow v2 授权、
凭据存储、守护进程重启持久性、确认服务器应用密码撤销及自建配置清理。
授权通过 HTTP 自动操作服务器 HTML 表单完成；交互式浏览器自动化仍未验证。
两个已批准地址的命名空间检查得到相同 UID 和根 ID；备用 origin 返回的跨 origin 登录地址
被拒绝。未修改服务器已有文件。

取消操作等待清理结束后才完成回执。失败或取消的流程会尝试撤销自己取得的密码，
但绝不撤销借用的验收凭据。未确认撤销以 `APP_PASSWORD_REVOCATION_UNCONFIRMED` 报告，
用户可在服务器安全设置中移除密码。中断建档后的清理无法确认远端撤销。
完整 SyncD 同步和自动端点切换仍不可用。
